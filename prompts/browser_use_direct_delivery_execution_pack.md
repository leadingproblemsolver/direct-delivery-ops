## ARTIFACT DEFINITION

Every recipient artifact must be a **Context Recovery Pack** or a narrow variant of it.

Allowed variants:

- source-linked project context pack;
- decision-history map;
- cross-source retrieval index;
- repository orientation file;
- forgotten-work inventory;
- recovered-source map.

Each pack must:

```yaml
context_recovery_pack:
  title:
  recipient_or_project:
  exact_function:
  source_boundary:
  sources_used:
    - title:
      url:
      source_type:
      relevance:
  recovered_context:
  decisions_or_threads:
  unresolved_or_disconnected_material:
  direct_retrieval_paths:
  explicit_unknowns:
  public_source_limitations:
  suggested_immediate_use:
```

Rules:

- one recipient;
- one bounded body of work;
- one clear function;
- public sources only unless explicit permission exists;
- direct links to original sources;
- evidence separated from inference;
- no diagnosis;
- no critique;
- no claim of completeness;
- no generic biography;
- no product pitch;
- no more than 1–3 pages unless the evidence requires more.

## UNIVERSAL TARGET GATE

A target passes only if at least 4 of 5 are true:

```yaml
target_gate:
  - explicit pain or a visible multi-source public corpus exists
  - the person or operator is realistically reachable
  - a genuinely useful artifact can be produced from ethical sources
  - the artifact can be completed in 60 minutes or less
  - the delivery could plausibly produce reuse, correction, referral, or learning
```

Reject:

- major industry leaders selected mainly for prestige;
- inaccessible corporate flagship projects;
- people whose private data is required before value can be demonstrated;
- targets where the output would mainly criticize their documentation or competence;
- generic AI audiences;
- targets with no visible corpus or declared problem;
- abandoned projects with no active human relationship surface;
- anyone requiring deceptive identity, paywall bypass, login circumvention, or prohibited scraping.

Prefer:

- accessible technical founders;
- developer-researchers;
- researchers with public papers/projects;
- consultants with reusable public work;
- maintainers of active small-to-mid-sized projects;
- community operators who personally interact with members.

# TRACK 1 — PAIN-TRIGGERED DELIVERY

## Goal

Find people who publicly state a concrete retrieval, continuity, or fragmented-context problem and deliver a directly relevant artifact draft.

## Search surfaces

Use a bounded combination of:

- Reddit;
- Hacker News;
- GitHub issues and Discussions;
- Indie Hackers;
- niche technical forums;
- product support forums;
- public Discord archives or indexed community pages when accessible;
- Google exact-phrase search across these surfaces.

## Search language

Start with high-signal phrases and expand using actual user wording:

```text
"I know I saved this somewhere"
"I know I wrote this already"
"cannot find old notes"
"cannot remember the filename"
"which repo had this"
"where is the original decision"
"starting from scratch again"
"search across all my files"
"search PDFs by meaning"
"my notes are a graveyard"
"lost project context"
"docs don't explain why"
"we keep re-deriving this"
"where was this discussed"
"cannot find the original thread"
```

Exclude:

```text
deleted file recovery
corrupted disk
photo recovery
generic productivity advice
tutorials
courses
SEO content
abstract AI-memory enthusiasm
```

## Qualification evidence

For every candidate collect:

```yaml
pain_candidate:
  handle:
  role_or_context:
  source_url:
  exact_quote:
  date:
  stated_problem:
  source_or_corpus:
  workaround:
  consequence:
  recurrence:
  accessibility:
  plausible_artifact:
  gate_result:
```

Do not infer pain beyond the public statement.

## Selection

Select the best 2 based on:

1. exactness of declared pain;
2. accessible public sources;
3. direct relevance of a bounded artifact;
4. reachable reply or contact surface;
5. likelihood of practical use.

## Production

For each selected target:

1. inspect only the public sources needed;
2. create one Context Recovery Pack variant;
3. verify every consequential statement;
4. draft one delivery message;
5. ask one validation question.

## Delivery draft

Use this structure, adapting it to the exact case:

```text
You mentioned [precise stated problem].

I used the public material connected to it to assemble a small [artifact name] that [specific function]. Sharing it in case it saves some reconstruction.

[artifact location]

What is the most important thing this still gets wrong or leaves hard to find?
```

No pitch. No call request. No follow-up sequence.

# TRACK 2 — ARTIFACT-FIRST TARGETED OUTBOUND

## Goal

Find accessible people with rich public project material, produce useful context-recovery artifacts without claiming they have a problem, and prepare direct outreach drafts.

## Candidate classes

Search for:

- technical founders with several public projects or long-running build logs;
- accessible maintainers of active small-to-mid-sized repositories;
- researchers with papers, talks, repositories, and project pages;
- consultants or analysts with repeated public frameworks and case material;
- public builders whose work is distributed across several sources.

Do not target major industry leaders merely because they are visible.

## Minimum public corpus

A candidate should have at least 3 relevant public sources, such as:

- project website;
- GitHub repository;
- issue or discussion history;
- public roadmap;
- technical blog posts;
- papers;
- talks;
- documentation;
- public build logs;
- interviews;
- newsletters.

## Candidate record

```yaml
artifact_first_candidate:
  person:
  role:
  project_or_body_of_work:
  public_sources:
  source_count:
  visible_continuity_or_retrieval_job:
  reachable_channel:
  proposed_artifact:
  immediate_use:
  gate_result:
```

Do not convert “many sources” into an unsupported claim that the person is disorganized.

## Selection

Select the best 2 based on:

1. accessibility;
2. useful public corpus;
3. artifact can expose real navigational value;
4. recipient can inspect it immediately;
5. artifact can be produced in 60 minutes or less.

## Production

For each selected target:

1. define one real job, such as:
   - reopen key project decisions;
   - navigate the project’s public source set;
   - recover unfinished public threads;
   - orient a contributor to major components;
   - connect papers, repositories, and active questions;
2. create one Context Recovery Pack;
3. label all inferences;
4. state the public-source boundary;
5. draft one message.

## Delivery draft

```text
I used only the public material around [project/body of work] to create a small [artifact name] that [specific function].

No pitch—I’m testing whether source-linked context-recovery artifacts like this are actually useful in practice.

[artifact location]

What did you expect this to surface that it missed?
```

Alternative:

```text
I noticed the public work around [topic/project] spans [named source types].

I assembled a small source-linked [artifact] so the key [materials/decisions/threads] can be scanned and reopened from one place.

[artifact location]

Is this useful enough to keep, or is it solving a problem you do not actually have?
```

# TOOL USE

Use all available tools when they increase operational effectiveness.

## Prefer

- exact search-engine queries;
- native platform search;
- GitHub search and APIs;
- site search;
- public RSS feeds;
- sitemaps;
- direct page extraction;
- repository cloning or structured repository access;
- PDF/document parsing;
- browser automation;
- lightweight scraping for repeated public pages;
- spreadsheets or structured JSON/YAML for tracking;
- code for deduplication, ranking, and link validation.

## Use scrapers when

- many similar public pages must be inspected;
- structured extraction saves substantial time;
- site access and terms allow it;
- provenance and source URLs remain attached.

## Do not scrape when

- a few pages are sufficient;
- the content is private, gated, or personal;
- volume does not improve target quality;
- the site prohibits the action;
- it would create relationship or privacy risk.

Do not use powerful tools merely because they exist.
